# LFM2.5-350M Command-Risk Classifier (kube-ordinal v3)

> **Status: proof of concept**, like the dataset it was trained on —
> published for reproducibility and scrutiny, not as a hardened
> production guard. The Limitations sections here and in the dataset
> card are the fine print that matters.

An advisory whole-statement risk classifier: reads one statement — a
kubectl/shell command, a script fragment, or a natural-language
operations request — and scores it **informative < mutating <
destructive**. A fine-tune of
[LiquidAI/LFM2.5-Encoder-350M](https://huggingface.co/LiquidAI/LFM2.5-Encoder-350M)
(bidirectional encoder, CLS pooling, linear head), trained on the
companion Agent Command Risk dataset (kube-ordinal config, v3 split).

Built for agent boundary guards: ~89 ms/statement on CPU f32 via
[candle](https://github.com/huggingface/candle) with no Python at
inference time. The export layout loads directly in the
`candle-lfm2-encoder` crate (`Lfm2SequenceClassifier::from_dir`); it also
loads in transformers via the checkpoint's config (`id2label` included).

## This model is advisory — read this part

- **Gate on the distribution, not the argmax.** Correct answers in our
  evals sit at ≥0.88 top-probability; the characteristic failure mode is
  a near-uniform distribution (e.g. 0.52/0.31/0.17) on genuinely
  ambiguous phrasing. Route low-confidence to a human or a bigger model.
- It classifies **text**, not your cluster. It cannot know whether a pod
  is controller-owned, whether a PVC holds the last copy, or what your
  RBAC would actually permit.
- It is not an authorization mechanism, and it is not adversarially
  robust: labels encode what text *says it does*, so an attacker who
  controls the text can evade it. Use it to catch accidents, not
  attackers.

## Evaluation (all splits published in the dataset repo)

| split | accuracy | severe (informative↔destructive) errors |
|---|---|---|
| kube test (command-shaped, held out) | 90.9% | **0** |
| holdout: NL assistant requests (never trained, any version) | 83.3% | **0** |
| holdout: security auditor | 90.0% | 3 |

Error character: mistakes are adjacent-severity and lean conservative
(mutating over-flagged as destructive on delete-shaped NL requests).
Known misses: audit-log deletion reads as informative; contested storage
patches (finalizer removal on pvc) read as mutating.

Version history on identical evals — the controlled experiment this
model falls out of: v1 (872 rows) 90.9% / 30.0% / 88.3%; v2 (+600
command-persona rows) 90.9% / 25.0% / 88.3% — no change; v3 (+300
natural-language rows) is the release. Surface-form coverage, not
persona variance, was the lever.

## Training

- Data: kube-ordinal v3 train/validation (1490/167 rows, 13 sources,
  gates and provenance documented in the dataset card).
- 6 epochs, AdamW lr 2e-5, linear warmup 6%, batch 16, bf16 autocast,
  max_len 256, seed 42; best-validation-accuracy epoch exported
  (0.964, epoch 4). Trainer script published in the training repo.
- Provenance: all training text is synthetic, generated by Anthropic
  Claude models (claude-haiku-4-5 for the persona corpus); labels follow
  a published house rubric; single-family caveat applies and is
  documented in the dataset card.
