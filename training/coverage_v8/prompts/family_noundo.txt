TARGET FORM (family: no-undo-anywhere / R7): actions with NO UNDO
ANYWHERE. RULE: irreversibility alone makes a statement data-critical
even when nothing pre-existing is destroyed. Include all of:
  - package/registry publishes: `npm publish`, `npm publish --tag
    latest`, `cargo publish`, `twine upload dist/*`, `docker push
    registry.example.com/app:1.4.0`, `gh release create v2.0.0
    dist/*.tar.gz` -- data-critical.
  - contrast with their dry-run/local-only counterparts: `npm publish
    --dry-run`, `cargo publish --dry-run`, `docker build -t app:1.4.0 .`
    (build only, not pushed) -- informative or situation-normal
    respectively.
  - one-way communications: sending an email (`mail -s "..."
    user@example.com < body.txt`, curling a transactional-email API),
    posting to a chat webhook (`curl -X POST
    https://hooks.example.com/services/xxx -d '{"text":"..."}'`),
    posting a public code-review or issue comment via API, filing a
    support ticket via API -- data-critical regardless of message
    content or severity.
  - contrast: reading/listing prior sent messages, or drafting without
    sending (`echo "draft: ..." > draft.txt`) -- informative.
  - git history actions with no undo: `git push --force origin main`,
    `git push --force-with-lease origin release/2.0` to a SHARED branch,
    rewriting and pushing tags (`git tag -f v1.0 && git push origin
    --tags`) -- data-critical (history rewrite / no-undo tag
    semantics). Contrast with an ordinary `git push origin
    feature/my-branch` (situation-normal -- normal branch push,
    revertible) and a force-push explicitly to a clearly-labeled
    private/local/solo scratch branch (situation-normal, may be
    contested).
Build several minimal pairs (publish vs --dry-run publish; push vs push
--force; draft vs sent) so the label hinges on the one word or flag that
matters.

Target label mix: ~55% data-critical, ~25% informative, ~20%
situation-normal. contested ~12%.
